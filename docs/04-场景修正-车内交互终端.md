# 场景修正 · 车内交互终端（In-Car HMI）

> 本文是对 `01-产品设计` 的**场景级修正**。原设计的假设是"手机端叫车 App"，实际场景是"乘客上车后的车内交互终端"。
> 两者生命周期几乎不重叠，因此产品定义、信息架构、页面地图需整体重写。
> 冲突时以本文为准，`01` 文档中与本文件冲突的部分作废。

---

## 1. 场景重新定义

### 1.1 一句话

> **这是一块装在无人驾驶出租车里的屏幕。乘客已经上车，车正在开。屏幕要做的是：让乘客安心、舒服、不无聊地把这段路坐完，并且在任何时刻都知道"现在什么情况、我能做什么"。**

### 1.2 产品边界（划清与手机 App 的界线）

| 阶段 | 归属 | 说明 |
| --- | --- | --- |
| 找车 / 选目的地 / 选车型 / 估价 / 下单 | 📱 手机 App | **车机不做** |
| 匹配派单 / 车辆来接 / 上车点导航 / 解锁上车 | 📱 手机 App | **车机不做** |
| **上车确认 / 身份校验** | 🖥️ 车机 | 从这一刻开始 |
| **行程中（环境控制 / 决策可视化 / 求助）** | 🖥️ 车机 | **核心** |
| **下车流程 / 开门 / 物品提醒** | 🖥️ 车机 | |
| **行程小结 / 评价** | 🖥️ 车机 | |
| 支付 / 开票 / 订单历史 / 钱包 / 优惠券 | 📱 手机 App | **车机只展示账单，不收款** |

### 1.3 场景的物理与心理约束（这些约束驱动了后面所有设计决策）

| # | 约束 | 对设计的强制要求 |
| --- | --- | --- |
| C1 | **公共设备，不是个人设备** | 不能有登录、注册、个人账户长驻。乘客下车即会话结束，个人数据要清除 |
| C2 | **乘客坐着，可能系着安全带** | 触控热区有限，主操作必须落在屏幕中下部的舒适可达区 |
| C3 | **无键盘输入** | 禁止文字输入。需要输入时只允许数字键盘（如手机尾号后 4 位），其余一律走语音或预置选项 |
| C4 | **观看距离 50~80cm，横屏** | 字号比手机大一档，一屏信息量要少，禁止密集列表 |
| C5 | **行驶中盯着屏幕会晕车** | 地图动效要柔、禁止大面积快速滚动、禁止需要持续专注的内容（长文、游戏） |
| C6 | **乘客可能想休息** | 默认是"安静的乘客侧"：信息可被扫视，但不主动打扰、不弹窗、不播放声音 |
| C7 | **没有司机可问，屏幕是唯一求助通道** | SOS / 客服必须一级可达（任何页面 ≤ 2 次点击） |
| C8 | **可能多名乘客共乘** | 需要"谁在控制这辆车"的控制权机制 |
| C9 | **白天强光 / 夜间行车** | 亮度自适应，夜间必须默认深色（减少眩光） |
| C10 | **车机会重置给下一位乘客** | 会话隔离，下车后清除个人痕迹 |
| C11 | **乘客是"被困"的，心理上需要掌控感** | 车辆行为要透明可解释（这是本产品最大的价值点） |

## 2. 原功能清单审计

**判定说明**：❌ 砍掉 ｜ ⚙️ 改造后保留 ｜ ✅ 保留并强化（车内核心）

### A. 账户与身份

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| A1 手机号 + 验证码登录 | ❌ | 车机不该有登录。**替代：上车校验**（输入手机号后 4 位 / 扫码，证明你是本单乘客） |
| A2 Token 登录态与续期 | ⚙️ | 改为**行程会话**：由车机后端签发、绑定当前订单、行程结束即失效，无 refresh |
| A3 首登引导（实名 / 紧急联系人） | ⚙️ | 改为**首次乘坐引导**：怎么开门、摄像头在哪、出事按哪里。这个在车内很有价值 |
| A4 游客体验模式 | ❌ | 场景不存在 |
| A5 大字模式 / 语音叫车 | ⚙️ | 大字模式保留（车内无障碍刚需）；"语音叫车"改为**车内语音助手** |

### B. 叫车主流程 —— **整块砍掉**

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| B1 自动定位 / 拖拽上车点 | ❌ | 手机端 |
| B2 上车点智能纠偏 | ❌ | 手机端 |
| B3 目的地搜索 | ❌ | 手机端。车内只保留"改目的地"，用**常用地点 + 语音**实现，不做全量搜索 |
| B4 地图选点 | ❌ | 手机端 |
| B5 智能目的地推荐 | ❌ | 手机端 |
| B6 车型选择 | ❌ | 车都上了，车型已定 |
| B7 预估价格与锁价 | ❌ | 手机端 |
| B8 附加选项（人数 / 行李） | ❌ | 手机端 |
| B9 预约用车 | ❌ | 手机端 |
| B10 途经点 | ✅ | **改目的地 / 加经停点是车内真实需求**，保留 |

### C. 派单与等车 —— **整块砍掉**

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| C1 匹配中动效 | ❌ | 手机端 |
| C2 车辆信息卡 | ⚙️ | 改为**车辆身份卡**：确认"我上的就是这辆车"（车牌、车型、车内编号） |
| C3 车辆实时位置推送 | ⚙️ | 语义反转：从"车来找我"变为**"我坐的车现在在哪、到哪了"**。SSE 与仿真引擎直接复用 |
| C4 等车倒计时 | ⚙️ | 改为**到达倒计时** |
| C5 车辆行为状态文案 | ✅ | **升级为车内第一核心功能**：决策可视化 |
| C6 上车点步行导航 | ❌ | 手机端 |
| C7 车辆召唤（鸣笛 / 闪灯） | ❌ | 手机端 |
| C8 解锁码开门 | ⚙️ | 反转为**下车开门**与**紧急开门** |
| C9 超时未上车处理 | ❌ | 手机端 |

### D. 行程中 —— **车内核心区，大幅扩张**

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| D1 实时地图 + 剩余时间 / 里程 / 费用 | ✅ | 主视图。费用改为"当前累计（预估）"，不涉及支付动作 |
| D2 决策可视化 | ✅ | **最大价值点，必须重点做**：礼让行人、前方拥堵、为何绕路、正在等待信号、为何减速 |
| D3 车内控制（空调 / 音乐 / 灯光） | ✅ | **大幅扩展为环境控制面板**（见 §3 新增功能） |
| D4 远程协助（呼叫安全员） | ✅ | 核心。车内是唯一求助通道 |
| D5 改目的地 / 加经停 | ✅ | 保留 |
| D6 行程分享 | ⚙️ | 弱化：本应在手机端。车内改为"**把行程同步到手机**"（扫码） |
| D7 SOS 紧急求助 | ✅ | **升级为分级的"紧急停车"**，这是车内独有的能力 |
| D8 下车点选择 | ✅ | 保留且强化：行程后段的核心操作 |
| D9 行程结束结算页 | ⚙️ | 去掉支付动作，改为**行程小结**（账单已由手机端处理） |

### E. 支付与订单 —— **大部分砍掉**

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| E1 自动扣款（模拟钱包） | ❌ | 手机端 |
| E2 优惠券抵扣 | ❌ | 手机端 |
| E3 费用明细 | ⚙️ | 保留**只读展示**，让乘客知道钱花在哪 |
| E4 行程报告（含轨迹回放） | ✅ | 保留在车内展示：里程 / 时长 / 减碳 / 轨迹。**ECharts 的落点** |
| E5 订单列表 | ❌ | 手机端。车内只保留"本次行程" |
| E6 电子发票 | ❌ | 手机端 |
| E7 评价与反馈 | ⚙️ | 保留在车内（下车前评价转化率最高），且**不做文本输入**，只做星级 + 标签 |

### F. 安全中心

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| F1 紧急联系人管理 | ❌ | 手机端 |
| F2 行程自动分享给紧急联系人 | ⚙️ | 保留**开关**（不在车机里管理联系人） |
| F3 运营区域（ODD）说明 | ⚙️ | 弱化为"本车可服务范围"信息，不作为独立页面 |
| F4 安全须知 | ✅ | 保留（车内看安全说明是合理的） |
| F5 历史录像调取 | ❌ | 手机端 |
| — | ➕ | **新增：车内摄像头 / 麦克风工作状态与隐私说明** |
| — | ➕ | **新增：紧急停车（分级）** |

### G. 消息与客服

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| G1 站内消息中心 | ❌ | 车机不该有消息中心，会变成"通知垃圾场"。改为**行程内一次性提示条** |
| G2 在线客服（规则机器人） | ✅ | 核心 |
| G3 FAQ | ⚙️ | 弱化为"帮助与安全说明"折叠页 |

### H. 个人中心 —— **整块砍掉**

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| H1 个人信息与头像 | ⚙️ | 仅显示"当前乘客：张女士"，无编辑 |
| H2 常用地址管理 | ⚙️ | 仅只读使用（用于快速改目的地），不可在车机增删 |
| H3 出行偏好设置 | ✅ | **提升为核心**：我的偏好（温度 / 音乐 / 安静模式）应在车内被继承并一键应用 |
| H4 钱包与优惠券 | ❌ | 手机端 |
| H5 行程统计报表 | ⚙️ | 改造：从"历史统计"变为**本次行程报告**（跨行程累计数据可选，需账号绑定） |
| H6 深色 / 浅色主题 | ✅ | 保留，且**默认跟随环境光自动切换** |

### I. 智能推荐

| 原功能 | 判定 | 说明 |
| --- | --- | --- |
| I1 首页智能目的地推荐 | ❌ | 手机端 |
| I2 自然语言叫车 | ⚙️ | 改造为**车内语音助手**："还有多久到""帮我调低空调""刚刚为什么停车" |
| I3 错峰 / 优惠提醒 | ❌ | 场景不存在 |

### J. 仿真控制台 —— **全部保留，且更重要**

车机场景需要模拟更多东西：环境控制的状态反馈、故障注入、多人共乘、亮度环境。

## 3. 需要新增的功能（车内独有）

按优先级排列。

### P0（不做就不像一个车内产品）

| # | 功能 | 说明 |
| --- | --- | --- |
| N1 | **欢迎与身份确认** | 上车第一屏：称呼（"欢迎，张女士"）+ 目的地确认 + 上车校验（手机尾号后 4 位）。解决"我上对车了吗" |
| N2 | **出发确认** | 系好安全带提示 + "开始行程"按钮（车不会自己启动，需要乘客确认。这与真实 Robotaxi 一致） |
| N3 | **环境控制面板** | 温度（左右分区）、风量、座椅加热 / 通风、氛围灯、遮阳帘、音量。含**预设场景**：睡眠 / 办公 / 放松 / 晕车舒缓 |
| N4 | **决策可视化（旅程解释器）** | 车辆当前在做什么、为什么。包含：正在礼让行人 / 前方信号灯 / 为何绕行 / 为何减速 / 还要经过几个路口 |
| N5 | **行程进度时间轴** | 不只是地图：一条"已出发 → 行驶中 → 即将到达"的阶段进度，配合剩余时间 |
| N6 | **分级停靠** | 「我想在前方下车」（正常，选下车站点）与「紧急停车」（红色，需二次确认 + 后果说明） |
| N7 | **下车流程** | 接近目的地提醒 → 车辆已停稳（不可开门时按钮为禁用态并说明原因）→ 开门 → **遗留物品提醒** → 送别 |
| N8 | **隐私与设备状态** | 车内摄像头 / 麦克风工作中标识、数据用途、本次会话数据在下车后清除 |

### P1（显著提升体验）

| # | 功能 | 说明 |
| --- | --- | --- |
| N9 | **多人共乘控制权** | 显示当前控制者，支持交接。共享舱场景必需 |
| N10 | **车辆状态透明化** | 电量、当前车速、所在道路、剩余里程。让乘客"看得懂这台车" |
| N11 | **语音助手** | 免手操作（系安全带时尤其有用）：问进度、调环境、问路况 |
| N12 | **无障碍套件** | 大字模式、高对比模式、语音播报开关、色盲友好配色 |
| N13 | **多语言** | 中 / 英切换（机场、高铁站场景的外国乘客） |
| N14 | **行程小结 + 评价** | 里程 / 时长 / 减碳 + 星级评价（无文本输入） |

### P2（加分，时间够再做）

| # | 功能 | 说明 |
| --- | --- | --- |
| N15 | 影音娱乐（音乐 / 播客 / 电台） | 需注意 C5（晕车）与 C6（不打扰）。**排在最后做** |
| N16 | 沿途信息（路过什么地方） | 与决策可视化配合，做"城市导览"式轻内容 |
| N17 | 晕车关怀模式 | 降低动效、调节空调、建议坐姿 |
| N18 | 把行程同步到手机 | 扫码带走轨迹与账单 |

## 4. 修正后的信息架构

### 4.1 生命周期与页面地图

```
【待出发】乘客刚上车，行程未开始
   /welcome          欢迎 + 车辆身份确认（尾号核对）
   /verify           上车校验（手机尾号后 4 位）— 仅当无法自动识别时
   /ready            出发确认（安全带 + 目的地 + 开始行程）
   /first-ride       首次乘坐引导（怎么开门 / 摄像头在哪 / 如何求助）

【行程中】核心，占 90% 使用时长
   /trip             ★ 主视图：地图 + 进度 + 剩余时间 + 决策气泡
   /trip/explain     车辆行为解释（点决策气泡展开）
   /cabin            ★ 环境控制（温度 / 座椅 / 灯光 / 音量 / 预设场景）
   /stop             ★ 停靠：我要在前方下车 / 紧急停车（分级）
   /help             ★ 帮助与客服（远程协助 / 客服会话 / 安全说明 / 隐私）
   /destination      改目的地 / 加经停（常用地点 + 语音，无全量搜索）
   /share            同步行程到手机（扫码）
   /preferences      我的偏好（温度 / 音乐 / 安静模式）一键应用
   /media            影音娱乐（P2）

【即将到达】
   /arriving         到达提醒 + 下车点确认 + 开门准备
   /alight           车辆已停稳 + 开门 + 遗留物品提醒

【已结束】
   /summary          ★ 行程小结（里程 / 时长 / 减碳 / 轨迹回放 + ECharts）
   /rate             评价（星级 + 标签，无文本输入）
   /farewell         送别 + 会话结束提示 + "已同步到手机"
```

### 4.2 屏幕布局范式（横屏车机）

```
┌────────────────────────────────────────────────────────────┐
│  状态条：车辆编号 · 电量 · 时间 · 摄像头工作中 · 语言/大字     │
├───────────────┬────────────────────────────────────────────┤
│               │                                            │
│  行程信息卡    │              主内容区                       │
│  （常驻左栏）  │  默认 = 地图（路线 + 车辆 + 决策气泡）        │
│               │  切页 = 环境控制 / 帮助 / 小结                │
│  · 目的地      │                                            │
│  · 剩余时间    │                                            │
│  · 剩余里程    │                                            │
│  · 当前动作    │                                            │
│               │                                            │
├───────────────┴────────────────────────────────────────────┤
│  底部功能条：行程 │ 环境 │ 停靠 │ 帮助 │ （娱乐）             │
└────────────────────────────────────────────────────────────┘
```

**关键决定**：行程信息卡**常驻左侧**，不随页面切换消失。因为在车内场景，"我什么时候到"是永远需要瞥一眼的信息，任何页面都不该把它藏起来。

### 4.3 交互原则（车内专属）

| 原则 | 说明 |
| --- | --- |
| **一眼可读** | 任何页面在 1 秒内能读出"现在什么情况" |
| **一键求助** | SOS / 客服在任何页面 ≤ 2 次点击 |
| **无键盘** | 只允许数字键盘；其余用预置选项或语音 |
| **不打扰** | 不主动弹窗、不播声音、不要求确认（除安全相关） |
| **可撤销** | 紧急停车等破坏性操作必须有二次确认与撤销窗口 |
| **误触保护** | 开门、紧急停车等按钮需要长按或二次确认 |
| **大热区** | 触控目标 ≥ 56×56px（比手机端的 44px 更大） |

## 5. 视觉风格调整

### 5.1 从"手机 App 风"改为"车内终端风"

| 维度 | 原设计（手机端） | 修正后（车机端） |
| --- | --- | --- |
| 主色调 | 明亮、白底为主 | **深色为默认**（夜间行车不刺眼），浅色为备选 |
| 对比度 | 常规 | **提高**（强光下可读），但避免刺眼，用柔和的深灰底而非纯黑 |
| 字号 | 手机尺度 | **整体大一档**，关键数字 2 倍 |
| 信息密度 | 中 | **低**（`VISUAL_DENSITY: 3`），一屏一个焦点 |
| 布局 | 单列竖屏 | **横屏双栏**（左信息 + 右内容） |
| 动效 | `MOTION_INTENSITY: 6` | **降到 4**：行驶中要柔和，避免晕车；但决策气泡的出现要清晰 |
| 圆角 | 20px 卡片 | 更大更柔（24~28px），触控亲和 |
| 交互 | 点击为主 | 大按钮 + 长按确认 + 语音 |

### 5.2 旋钮取值（修正）

| 旋钮 | 原值 | 修正值 | 理由 |
| --- | --- | --- | --- |
| `DESIGN_VARIANCE` | 7 | **5** | 车机是功能型界面，不是营销页面。乱会降低可读性 |
| `MOTION_INTENSITY` | 6 | **4** | 行驶中动效过多会加重晕车，也可能分散注意力 |
| `VISUAL_DENSITY` | 4 | **3** | 观看距离更远、环境更复杂，信息要更少更大 |

> 延续你"更柔和"的要求：车内终端用**深色柔和底 + 低饱和 + 大圆角 + 极弱发光**，避免"科技大屏"的霓虹俗套。
